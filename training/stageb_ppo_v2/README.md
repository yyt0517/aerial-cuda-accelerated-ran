# 跨时隙服务选择 PPO

本轮沿用神经修复和原生物理验证能力，把学习任务收缩为完整可行方案之间的跨时隙服务选择。CTBS 裁剪、需求上限掩码、业务权重和服务缺口权重均关闭；所有用户使用相同的奖励系数。旧 `stageb_ppo` 和旧检查点保持冻结。

## 原因与针对性修改

旧版只有 384 个教师状态（每 seed 64 ms），在线训练 6144 个决策、24 次 actor 更新。保存的第 1/6/12 轮 critic 解释方差均约为 0，终轮值均值 −19.25，目标均值 −274.91。训练采样的 token 约 63% 不同于相同前缀下的贪心选择。旧队列代价约为有效完整包奖励的 4–5 倍，完整 TTL 内累积的代价相当于 4 个包。以上是诊断证据，不能视作各因素的独立因果效应。

新版使用以下机制：

- `Catalog` 复用冻结的 79 特征神经修复模型 `tb_joint_repair_20261027_train_v1/repair.npz` 和已有 `NativePhy`。等权 DPLS 解始终保留，追加单步/耦合物理邻域与神经候选，按完整方案精确验证，至多保留 16 个逐用户服务量不同的方案。
- 候选必须满足当前状态原始 PFQ 出队量的 ρ0.90 下界，并保留至少 98% 的 DPLS 解即时等权期望成功字节。使用相同物理验证器重算全部候选，PPO 采样后不修复、不替换动作。
- 小型共享 UE 网络对完整候选评分。固定即时物理先验加可训练残差；残差末层零初始化，起点的确定性决策就是同候选池物理贪心。复用神经修复权重，服务选择网络重新初始化，不延续旧失效 GRU 的权重。
- 状态包含 FIFO 清洁/受损剩余量、队首剩余量与年龄、临近 TTL 比例、清洁部分包进度，以及候选逐 UE 的出队、资源数、BLER、SINR 和可能完成的整包量。没有业务类别系数或服务缺口乘权。
- 基础奖励为 `(完整成功包 payload − 全包过期 payload − 队列字节/400)/86400`。再加清洁部分包进度的势函数差 `γΦ(s′)−Φ(s)`；其折扣和只留下边界项。完整成功包要求此前所有分段 CRC 成功，原生轨迹结束后独立 FIFO 重建核验。
- critic 重新初始化，隐层改用 SiLU 并加入 LayerNorm；奖励统一缩放 0.01，初始偏置由首轮训练均值估计。三个连续种子轨迹分别 bootstrap、分别计算 GAE，不跨 seed 接续。

## 冻结协议

正式训练：seeds 41–43，各 4000 TTI PFQ 预热、512 TTI 等权 DPLS 稳定化，再各 12×1024 个 PPO 决策；共 36,864 个在线学习决策，是旧版的 6 倍。单条 rollout 512 ms，超过 TTL 200 ms。γ=2^(−1/400)，λ=0.999；每轮最多 8 次 actor 更新、8 轮 critic 拟合。完整分布 KL 上限 0.02；超出时恢复模型和优化器再降低学习率。固定预算结束不等于证明收敛。

开发验证：seeds 44–45，4000 预热＋4000 稳定化＋4000 测量＋400 随访。比较最终 PPO 与同候选池物理贪心，并复用旧等权 DPLS、PFQ、旧 PPO 的相同 8001–12000 到达窗口。固定最终检查点，不用验证结果选模。44–45 已有开发暴露，不称未见测试；311–315 不使用。

当前实现每个时隙仍执行完整等权 DPLS 以获得参考解，再建立候选池。因此本轮隔离服务选择学习，不声称搜索加速。相对旧 PPO 的恢复不能全部归因于强化学习；只有相对同候选池物理贪心的结果才能评估学习残差的增益。

## 入口与证据

在仓库根目录及已有 CUDA 训练环境运行：

```bash
python -m unittest discover -s training/stageb_ppo_v2/tests -v
python -m training.stageb_ppo_v2.campaign --out /absolute/path/to/new_run
python -m training.stageb_ppo_v2.evaluate --root /absolute/path/to/new_run
```

`--smoke` 仅用于完整流程检查，不构成训练充分性证据。运行目录保存协议、源码/检查点哈希、逐轮轨迹、概率回放、GAE 审计、优化器与随机状态、原生动作和整包核验。完整诊断与本轮实验输出位于 `deliverables/ppo_diagnosis_continue_20261030_v1/`。

`rewards.csv` 来自冻结的旧原生适配器，保留旧 `reward` 列以兼容历史审计；本轮只使用其中的完整包、过期和队列分项。实际学习奖励保存在 `long_credit_rewards.csv` 及各轮 `rollout_*.pt` 中，由 `long_credit_validation.json` 独立核验，不能误用兼容列绘制本轮学习收益。

## 优化步数续训对照

前六轮整批训练的单轮分布 KL 仅约 10^-7。为检验 actor 实际优化步数不足的问题，另设 `refine` 分支，从同一第六轮检查点恢复 actor、critic、两个优化器与随机状态；原生重放 10656 TTI 历史以恢复同一决策状态，逐步核验 PPO 前缀奖励，并核对终端候选特征。首个续训 rollout 还需与整批分支第七轮的状态、动作、奖励和分布逐项一致。

唯一优化规则变化是 actor 使用 128 状态小批量，8 个 epoch 对应最多 192 次优化步，原整批规则为 8 次。每个 epoch 后计算整个行为分布的 KL；超限时同时恢复该 epoch 前的参数与 Adam 状态并降低学习率。候选、奖励、状态、critic 训练和全部无 CTBS 等权约束保持一致。固定训练到第十二轮，不按 PPO 验证结果选模。

```bash
python -m training.stageb_ppo_v2.refine --source /absolute/path/to/fullbatch_run --out /absolute/path/to/new_continuation
python -m training.stageb_ppo_v2.evaluate --root /absolute/path/to/new_continuation --arms ppo
```

最终续训链包含 18,432 个继承决策与 18,432 个新增决策；原整批分支另行完成其十二轮训练。两分支合计 55,296 个在线学习决策，精确重放不重复计为新样本。同候选池物理贪心轨迹按哈希与固定协议复用。整批和小批量的差异、独立采样审计与原生前缀证据均单独保存。

## 本轮结果

开发 seeds 44–45、各 2 秒成熟 cohort 的最终均值：小批量 PPO 完整包 payload 为 1240.686 Mbps，对同候选池贪心的 1237.848 Mbps 增加 0.229%；过期率由 0.851% 降至 0.663%。但平均成功包时延由 5.654 增至 7.012 ms，P95 由 10.0 增至 24.5 ms。双方都成功的同一批包也更慢，不能只归因于成功人群改变。

训练链完成 36,864 个决策、1200 次接受的 actor 更新，原生与独立采样/GAE 审计通过；两个 seed 均未通过平均/P95 时延门槛，未晋级，未证明收敛。完整解释与数据见 [报告](../../Doc/evidence/2026-10-30/ppo_service_choice/report.txt)。当前奖励缺少直接的整包等待或尾时延约束；后续奖励设计建议仅作为待验证方向，没有计入本轮实现结果。
